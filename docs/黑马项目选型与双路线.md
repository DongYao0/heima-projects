### ⚠️ 修正 1：智链云途 —— 不是"资料还少"，是"营销资料多、代码资料少"

官方 2026-08 / 09 已经放出了相当完整的架构说明，可以确认的技术画像：

- **业务载体**：物流全链路（下单 → 揽收 → 转运 → 配送 → 签收），20+ 微服务，客户 / 快递员 / 网点 / 司机 / 后台多端
- **分层**：访问层 → 网关层 → 业务服务层 → **AI 智能平台** → 数据层 → 基础设施层
- **Java 侧**：Spring Cloud Alibaba + RabbitMQ + Redis + Nacos + Seata + XXL-JOB
- **数据侧**：MySQL + MongoDB + Neo4j + ElasticSearch
- **AI 侧**：LLM + Agent + BERT（文本分类）+ XGBoost（业务预测）+ Embedding
- **AI 框架**：LangChain + LangGraph + MCP
- **关键架构决策**：Java 承担确定性业务服务，Python 承担 AI 模型服务，跨语言协同
- **设计理念**：AI 做理解与推理，确定性程序做计算与校验；如物品识别用 BERT（置信度 ≥0.9 直出）+ LLM 兜底的双层策略

所以准确的表述是：**架构与理念已公开，成套代码 / 逐集视频尚未流出**。这不影响把它当成目标形态参考——它恰好就是"Java 业务 + Python AI"的标准答案模板。

### ⚠️ 修正 2：天机学堂 AI 版不是"SpringBoot 单体"

官方拆解是 **Spring Cloud Alibaba 微服务 + Spring AI + 多智能体**，服务拆分为用户 / 课程 / 订单 / 学习记录等，基线是 Spring Boot 3.x + Java 21。

这意味着它在能力层上 **与黑马商城重叠（微服务层）**，而不是与苍穹外卖重叠（单体层）。你把它放在"AI 应用"行是对的，但别把它当单体项目的替代品。

### 补充：AI 应用层内部也重叠

天机学堂 AI 版 和 智链云途 都是"Java 微服务 + AI 融合"，**二选一即可**。区别在取向：

| | 天机学堂 AI 版 | 智链云途 |
|---|---|---|
| AI 技术 | Spring AI + 多智能体 | LangChain/LangGraph + MCP + 传统 ML（BERT/XGBoost） |
| 语言边界 | 全 Java | Java 业务 + Python AI 双语言 |
| 适合 | 想留在 Java 生态内做 AI 集成 | 想练跨语言微服务协同（更贴你的目标） |

**按你"Java 后端 + Python AI 服务 + Vue 前端"的合作目标，选智链云途。**

## 二、能力层 → 项目映射（每层只留一个）

| 能力层 | 候选 | 建议保留 | 理由 |
|---|---|---|---|
| Web 基础 / 单体 CRUD | 苍穹外卖、云岚到家、美多商城、黑马头条 Django | **苍穹外卖**（Java）/ **美多商城**（Python） | 外卖业务链路最完整，资料最全；云岚到家作为 O2O 变体按需再看 |
| 缓存与并发 | 黑马点评 | **黑马点评** | 无替代品。秒杀 / GEO / HyperLogLog 是面试高频题源 |
| 微服务治理 | 黑马商城、黑马头条 Java 版 | **黑马商城** | Nacos / Gateway / OpenFeign / Seata / ES / MQ 全覆盖，一条主线讲完 |
| 分布式一致性 | 万信金融、闪聚支付 | **二选一** | 万信金融偏事务理论，闪聚支付偏支付链路落地。要讲分布式事务选万信，要讲业务闭环选闪聚 |
| 领域特化 | 探花交友、云岚到家 | **按需，不排主线** | Mongo + IM / 地图 + 小程序，属于"用到再查" |
| AI 融合 | 智链云途、天机学堂 AI 版 | **智链云途** | 跨语言协同，贴合作目标 |

**被挤掉的项目不是没用，是不该占主线时间**：黑马头条 Java 版被黑马商城覆盖（都是微服务全家桶），探花交友 / 云岚到家属领域特化，天机学堂 AI 版与智链云途重叠。

## 三、双路线

### Java 组

```
苍穹外卖（单体 CRUD + 业务闭环）
   ↓
黑马点评（Redis 深水区：缓存三兄弟 / 秒杀 / GEO / UV）
   ↓
黑马商城（微服务治理全家桶）
   ↓
万信金融 或 闪聚支付（分布式一致性，二选一）
```

### Python 组

```
美多商城 或 黑马头条 Django 版（二选一，覆盖 Web 后端）
   ↓
AI 服务方向（模型服务化 / 推理接口 / 向量检索）
```

### 合流点

**智链云途**是两条线天然的汇合处——它本身就是 Java 业务服务 + Python AI 服务的跨语言架构。所以它不该被当成"第 12 个项目"，而是**双路线的终点形态**：

```
Java 组（4 个）─┐
                ├→ 智链云途（合流：跨语言协同 + AI 融合）
Python 组（2 个）─┘
```

这也解释了为什么"项目列表刷满"没意义：前面 6 个是**能力储备**，最后 1 个是**能力组合**。

## 四、真正拉开差距的部分：改造清单

原则：每个改造都要有 **可验证的产出**（接口 / 指标 / 压测数据 / 对比报告），否则简历上写不出来。

### 苍穹外卖

1. **AI 客服**：意图识别 + Function Calling 查订单 / 改地址，失败兜底转人工。产出：意图准确率 + 转人工率
2. **订单超时自动取消**：Redis ZSet 延迟队列 → 对比 RocketMQ 延迟消息，写对比报告
3. **缓存一致性**：菜品 / 套餐缓存，做 Cache Aside + 延迟双删，用 JMeter 打穿缓存前后 QPS 对比

### 黑马点评

1. **秒杀升级**：Lua 预扣 + 异步下单 → 再加库存对账任务（Redis vs DB 差异检测）
2. **UV 精度实验**：HyperLogLog 与精确 Set 在同一批流量下做误差率报告（这是能讲 5 分钟的东西）
3. **GEO 压测**：附近店铺按距离排序，对比"全表算距离" vs "GEO + 分页"的耗时曲线

### 黑马商城

1. **推荐服务（Python）**：召回（ItemCF / 向量）+ 排序，gRPC 暴露给 Java 商品详情页
2. **事务方案对比**：Seata AT 换成 TCC，同一笔下单流程两套实现，写 TCC 空回滚 / 悬挂问题的处理
3. **可观测性**：接 SkyWalking，把一次下单的跨服务链路截图作为产出

### 万信金融 / 闪聚支付（若选）

1. 把异常补偿做成**可重放的对账脚本**：造 100 笔异常单，跑脚本后对账归零
2. 支付回调幂等：同一笔回调重放 10 次，账户余额只能变一次

## 五、几个容易忽略的坑

1. **黑马点评和苍穹外卖都碰 Redis，但不是重复**。外卖是"业务里怎么用缓存"，点评是"缓存/并发本身怎么设计"。顺序不能反——先有业务感，再抠原理。
2. **版本坑**：苍穹外卖（2023）基线是 Spring Boot 2.x + JDK 11/17；黑马商城（2024）是 Spring Boot 3.x + JDK 17 + Spring Cloud Alibaba 2023.x。两套依赖别混抄，`javax` → `jakarta` 会直接编译失败。
3. **黑马头条搜的时候要认准语言**：Java 微服务版 vs Django 版是两个完全不同的课，同名不同物。
4. **智链云途现在不适合作为"第一个 AI 项目"**。代码未成套流出，且它假定你已具备微服务 + Python 双栈基础。放在路线末端，当前先当架构参考读。
5. **天机学堂 AI 版若你明确不学 Spring AI，跳过是对的**，但要补一个替代：用 LangChain/LangGraph 在 Python 侧做一个 Agent 服务，否则 AI 融合这一层会是空的。
